# 🛠️ Troubleshooting & FAQ

Having issues running LiteRAG? Find common problems and their solutions below.

## 🛑 Initialization Errors

### `RuntimeError: LiteRAG not initialized`
* **Symptom**: Calling `engine.query()` or `engine.aquery()` immediately throws an error.
* **Solution**: You must call `engine.initialize()` before executing queries. This loads the graph data and warms up the vector store.

### `ValueError: Could not load required entities or relationships data`
* **Symptom**: Engine fails during initialization.
* **Solution**: Verify your `data_dir` in `literag_config.yaml`. It must point to a directory containing the parquet files generated by GraphRAG (specifically `entities.parquet` and `relationships.parquet`).

### `ValueError: api_key is required when not using LiteLLM proxy`
* **Symptom**: Configuration validation fails.
* **Solution**: Either set `api_key: "your_key"` in `literag_config.yaml`, export it as an environment variable (e.g., `export GEMINI_API_KEY="..."`), or set `use_litellm: true` if routing through a local proxy.

## Performance & Quality Issues

### 🐌 Query Latency is Too High
If your queries are taking longer than expected (e.g., > 3 seconds), the algorithm is exploring too much of the graph.
* **Solution 1**: Reduce `max_exploration_depth` (e.g., from `3` to `2`).
* **Solution 2**: Reduce `max_nodes_per_anchor` (e.g., from `50` to `20`).
* **Solution 3**: Increase `degree_influence` (e.g., `0.10`) to penalize generic hub nodes more aggressively, cutting off massive branches of the graph.

### ❓ No Anchors Found ("No relevant information found")
* **Symptom**: The engine returns an empty answer immediately.
* **Solution**: The initial vector/keyword search didn't meet the minimum threshold. 
  1. Lower `min_anchor_score` in your config (e.g., to `0.20`).
  2. Ensure your embedding model is working correctly and the `lancedb` folder was properly generated.

### 💸 High Token Usage (Context Window Too Large)
* **Symptom**: LiteRAG is consuming too many tokens per query.
* **Solution**: 
  1. Lower the `max_context_tokens` limit in your config (e.g., to `4000`).
  2. Lower `safety_net_k` (from `5` to `2`) or set `enable_safety_net: false`. Raw text chunks consume significantly more tokens than LiteRAG's Reasoning Chains.

## 🧵 Concurrency & Async Errors

### `RuntimeError: explore() cannot be called from a running event loop`
* **Symptom**: Occurs when running LiteRAG inside an ASGI web framework like **FastAPI**.
* **Solution**: You are using the synchronous `engine.query()` inside an async event loop, which causes ThreadPool deadlocks. Switch to the native async method: 
  ```python
  result = await engine.aquery(query)
  ```
