## 💡 What is LiteRAG?

Current GraphRAG systems (like Microsoft GraphRAG or LightRAG) rely heavily on LLMs to navigate knowledge graphs. This causes a "Performance Paradox": as the dataset grows, latency and API costs explode ($O(N)$ scaling).

**LiteRAG** shifts the paradigm. We completely remove the LLM from the graph traversal loop. By using **Algorithmic Graph Traversal** (dynamic semantic thresholding + hub penalization) and **Reasoning-Chain Context Assembly**, LiteRAG achieves State-of-the-Art (SOTA) multi-hop reasoning at a fraction of the cost.

### ✨ Key Features
- ⚡ **$O(1)$ Latency:** Traversal is done via fast, parallel algorithms, not LLM inference.
- 💰 **99% Cost Reduction:** Uses ~2,000 tokens per query, compared to millions in agentic systems like DRIFT.
- 🎯 **Multi-Strategy Anchors:** Combines Semantic, Exact Keyword, Fuzzy, and Community matching to find perfect starting nodes.
- 🧠 **Reasoning Chains:** Prompts the LLM with dense causal logic (e.g., `A → [relationship] → B`) instead of raw text chunks, preventing context pollution.

To rigorously evaluate LiteRAG against current SOTA paradigms, we are open-sourcing the **DistComp Corpus** on Hugging Face.

👉 **[Download the DistComp Dataset on Hugging Face](https://huggingface.co/datasets/macarronesc/DistComp)**

Derived from high-impact academic literature in Distributed Computing, the dataset evaluates complex semantic drift and graph-based reasoning across disjoint knowledge clusters. 

Crucially, **we provide fully pre-indexed Microsoft GraphRAG artifacts** (Parquet files, LanceDB vector stores) stratified into splits of `{40, 80, 160, 320, 640, 1280}` documents. This allows researchers to bypass the costly indexing phase and immediately evaluate retrieval performance at scale.

## ⚙️ Architecture Overview

LiteRAG operates in three highly optimized phases, utilizing the indexing structure generated by Microsoft GraphRAG (consuming its parquet files):

<div align="center" style="margin: 30px 0;">
    <img src="./docs/architecture.png" width="100%" alt="LiteRAG Architecture Diagram">
</div>

1. 🎯 **Anchor Discovery**: Finds starting nodes using a fusion of Semantic Similarity (LanceDB), Lexical Overlap (BM25/Fuzzy), and Community relevance.
2. 🕸️ **Parallel Graph Exploration**: A Zero-LLM Breadth-First Search (BFS) that dynamically calculates semantic thresholds. It explicitly penalizes "Generic Hubs" while protecting domain-specific "Topic Hubs".
3. 🔗 **Reasoning-Chain Assembly**: Instead of dumping raw text into the prompt, LiteRAG serializes graph logic into dense causal chains (`Entity A -[Relationship]-> Entity B`), radically reducing token footprint.

## 🛠️ Installation

We recommend using a virtual environment. The addition of the `setup.py` module allows you to install LiteRAG dynamically in editable mode, making the `literag` package importable anywhere in your environment.

```bash
# Clone the repository
git clone https://github.com/macarronesc/LiteRAG.git
cd LiteRAG

# Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install LiteRAG and its dependencies in editable mode
pip install -e .
```

## 🚀 Quick Start

**Prerequisite:** LiteRAG acts as the *retrieval and generation* engine. It requires a pre-indexed Knowledge Graph. You must point LiteRAG to a directory containing GraphRAG's parquet outputs (`entities.parquet`, `relationships.parquet`, etc.), which you can download from our [Hugging Face dataset](https://huggingface.co/datasets/macarronesc/DistComp).

### 1. Configure LiteRAG
Copy and paste your API keys and data directory to the config file:
```bash
cp literag_config.example.yaml literag_config.yaml
```

Then edit `literag_config.yaml` to point to your data and add your API key:

```yaml
data_dir: "example-data/doc40/output"
api_key: "YOUR_API_KEY"
```

### 2. Run the Example Code
We provide a plug-and-play example utilizing the data in `example-data/`.

```python
import asyncio
from literag import LiteRAG, LiteRAGConfig

async def main():
    # 1. Load Configuration
    config = LiteRAGConfig.from_yaml("literag_config.yaml")
    
    # 2. Initialize Engine (Loads Graph Data & LanceDB)
    engine = LiteRAG(config)
    engine.initialize()

    # 3. Query the Graph
    query = "What technologies enable edge computing for IoT?"
    result = await engine.aquery(query)

    print(f"🤖 Answer: {result.answer}")
    print(f"⏱️ Latency: {result.latency_ms / 1000:.2f}s | 🪙 Tokens: {result.tokens_used}")

if __name__ == "__main__":
    asyncio.run(main())
```

*For a ready-to-run script, check out `example.py`.*

## 📊 Comprehensive Benchmarking Suite

LiteRAG includes a unified, "fair-fight" benchmarking suite to compare performance across GraphRAG, LightRAG, HiRAG, Google FileSearch, and LiteRAG. 

It utilizes a rigorous **Three-Pillar Evaluation Metric**:
1. **LLM-as-a-Judge (60%)**: Evaluates Correctness, Completeness, and Relevance.
2. **Semantic Similarity (25%)**: Vector alignment between prediction and ground truth.
3. **Lexical Overlap (15%)**: ROUGE-L F1 scores to penalize severe hallucinations.
