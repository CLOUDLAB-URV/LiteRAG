# ⚖️ LiteRAG Benchmarking Suite

A "Fair-Fight" unified evaluation framework for modern GraphRAG systems. 

Unlike standard QA datasets that test superficial fact-hopping, this suite evaluates **deep, abstract conceptual synthesis** across different RAG architectures while tracking real-world operational costs.

## 🎯 The Three-Pillar Evaluation Metric
To accurately evaluate GraphRAG, we use a composite accuracy metric ($S_{total}$) that penalizes hallucinations and rewards logical coherence:

1. **LLM-as-a-Judge (60%):** Evaluates *Correctness*, *Completeness*, and *Relevance* against a Ground Truth.
2. **Semantic Similarity (25%):** Embedding cosine similarity between the generated answer and ground truth.
3. **Lexical Overlap (15%):** ROUGE-L F1 score acting as a strict penalty against severe hallucinations.

## 🚀 Supported Engines
* **LiteRAG:** (Ours) Adaptive Graph-Native Search.
* **Microsoft GraphRAG:** Basic, Local, Global, and DRIFT modes.
* **LightRAG:** Local, Global, Hybrid, Mix, and Naive modes.
* **HiRAG:** Hi, Local, Global, Bridge, and NoBridge modes.
* **Google FileSearch:** Gemini-native managed RAG baseline.

## 🚀 Quick Start

### 1. Setup Environment
Ensure you have the benchmark dependencies installed (these include plotting libraries):
```bash
pip install -r requirements.txt
```

### 2. Configure Your Proxies & Data
Update the configuration files in `benchmark/config/`. 
*   If you are testing LiteRAG vs GraphRAG, ensure your paths in `literag_config.yaml` and the `graphrag_dir` point to your indexed parquet files.
*   Update `.env` with your OpenAI or Gemini keys.

### 3. Run a Comparison
Compare LiteRAG against Microsoft GraphRAG Local search using the provided 40-document sample dataset:

```bash
python run_benchmark.py \
    --prompts ../example-data/40docs.json \
    --literag-config ../literag_config.yaml \
    --graphrag-dir ../example-data/doc40/ \
    --engines literag graphrag_local \
    --concurrency 2
```

### 4. Viewing Results
Results are saved to a timestamped folder (e.g., `./benchmark_results_20250101/`). The suite automatically generates:
*   📄 **`benchmark_report.html`**: A beautiful, interactive HTML summary with embedded charts.
*   📈 **`plots/`**: High-resolution PNGs comparing Latency, Token Usage, Cost, and Accuracy (Heatmaps and Boxplots).
*   💾 **`benchmark_results.csv`**: Raw telemetry data for custom analysis.
*   📝 **`responses/`**: The complete text of every answer generated by every engine, along with the Judge's reasoning.

## 🔧 Adding a New Engine
Our framework uses an Adapter Pattern. To add a new RAG system:
1. Create a new adapter in `code/engines_yourname.py` that inherits from `SearchEngineInterface`.
2. Implement the `initialize()` and `search()` methods.
3. Register the engine in `run_benchmark.py`.
